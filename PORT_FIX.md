# Исправление проблемы "No open ports detected"

## Проблема
Render ищет открытые HTTP порты, потому что сервис создан как **Web Service**. Telegram боты работают через long polling и не открывают HTTP порты.

## Решение
Добавлен простой HTTP сервер, который:
- Открывает порт для Render (по умолчанию 10000)
- Отвечает "Bot is running" на GET запросы
- Работает в фоновом потоке, не мешая боту

## Что изменено

### 1. [`bot.py`](bot.py:1)
- Добавлен импорт `Thread` и `HTTPServer`
- Добавлен класс `HealthCheckHandler` для обработки HTTP запросов
- HTTP сервер запускается в отдельном потоке перед запуском бота

### 2. [`render.yaml`](render.yaml:1)
- Создан файл конфигурации для Render

## Как это работает

1. При запуске бота создается HTTP сервер на порту из переменной `PORT` (Render автоматически устанавливает эту переменную)
2. HTTP сервер работает в фоновом потоке и не блокирует работу бота
3. Render видит открытый порт и считает сервис работающим
4. Бот продолжает работать через Telegram API (long polling)

## Проверка

После деплоя в логах Render вы увидите:
```
HTTP сервер запущен на порту 10000
Бот запущен...
```

И больше не будет сообщений "No open ports detected".

## Альтернативное решение

Если хотите использовать Background Worker вместо Web Service:
1. Создайте новый сервис на Render
2. Выберите тип **Background Worker** (не Web Service)
3. В этом случае HTTP сервер не нужен - можно удалить соответствующий код

Но текущее решение работает и не требует пересоздания сервиса.
